# 项目记忆数据库

本库帮助开发 agent 找到当前规则、接口和源码，**不修改游戏 CFG、玩家 Mod 或存档**。现行知识在 `docs/knowledge/`，详细设计在 `docs/design/`；规则入口是根目录 `AGENTS.md`。旧项目中的历史知识已在本机备份，不能继续作为当前单 DLL 架构的依据。

## 使用

```sh
python3 -B tools/project_memory.py index
python3 -B tools/project_memory.py search 'UNO 摸牌摸光洗牌'
python3 -B tools/project_memory.py search 'UpSession' --scope navigation --mode lexical
python3 -B tools/project_memory.py status --check
python3 -B tools/project_memory.py compact
```

macOS 默认使用 Apple NaturalLanguage 的中文句向量与词项混合检索，首次需系统模型和 swiftc；Windows/Linux 默认构建词项索引，不需要模型、网络服务或额外 Python 包。任意平台可显式 `index --backend lexical`。模型不可用时明确报错，可主动选择词项后端；不会把词项检索冒称为语义检索。`search --mode auto` 根据已建库的实际后端选择查询方式。

搜索不重建索引、不读取知识原文，只取默认前三段，每段最多 550 字，单次最多五段。返回仓库相对路径、行号、命中标题和索引代次；先按线索定位，再读源码。分数不是正确率。无结果或纯语义结果缺少词项支持时标记需要核对。已知文件/符号时直接定向查代码，不必先查库。

## 优化与可靠性

- **内容治理**：当前状态、配置、源码导航与验证边界分开，去掉旧路径和逐次流水；详细设计保留但不反复进入默认上下文。不要把未知结果补写成已完成。
- **增量更新**：文件状态没变则不读内容；仅时间戳变化但字节相同时，只更新状态，不重算向量或清掉有效缓存。只有新增或改动的片段需要计算向量。
- **共享与上下文**：相同标题和内容共用片段，多来源保留；标题和片段内部空白参与指纹，避免错误合并。删除一份来源不会删除其他文件仍引用的知识。
- **检索成本**：中文词项使用二字组合，向量保留 float32；词项查询批量执行，避免逐词往返 SQL。缓存最多 64 个查询，正文只取最终少量命中。
- **并发与中断**：向量生成在事务外；提交前重新核对文件、白名单和数据库代次，再在事务内替换。并发变化会明确要求重试，失败保留上一代；搜索发现代次变化时不写入混合结果缓存。
- **可移植**：库内来源和查询结果使用相对路径；模型改变必须重算向量，`index --force` 支持换模型。SQLite 外键、完整性检查与有限缓存覆盖删除、失败回滚及并发场景。
- **维护**：`status --check` 比较白名单文件状态和索引后端，不读知识全文；它不是文件编辑锁。更新知识后必须 `index`，删除较多内容后可 `compact` 回收空间。不要每次提问重建。

## 共享边界

仓库上传人可读的记忆、`tools/project_memory_sources.json` 白名单、检索/向量工具、测试和小样本基准。`.project-memory/` 是自动生成的本机索引，继续忽略；不上传旧数据库、个人聊天、账号、玩家模组、存档或查询缓存。默认禁止 `qa/`、`dist/`、`research/`、`archive/` 等目录进索引，软链接也不能越出仓库。

新增长期有效知识应替换对应条目。具体游戏审计报告留在 QA 中；只把会影响后续开发的结论写回现行知识。接近完工审计流程见 [完工审计](workflow/完工审计.md)。

## 验证

```sh
python3 -m unittest discover -s tests/Memory -v
python3 -B tools/benchmark_project_memory.py
python3 -B tools/benchmark_project_memory.py --mode lexical
```

基准为十条固定查询的前三条命中、冷热延迟和输出上限检查，不代表任意问题都准确。测试只使用临时库和假向量；实际 macOS 中文向量另行基准，Linux CI 从白名单重建词项库。清理前后知识范围不同，因此空间/耗时对比是迁移效果，不是同规模算法性能宣称。

2026-09-19 迁移结果：原库 2,281,472 字节、93 个片段、34,617 字正文；新库压缩后 458,752 字节、39 个片段、10,058 字正文。18 项回归测试通过，实际混合检索与词项检索各 10/10 条查询命中预期前三结果；临时空目录可重建纯词项库。完整性检查正常，无外键错误。详细设计独立保留，不通过删掉用户约定来缩小索引。测量结果见 [基准记录](knowledge-optimization-20260919.json)。
