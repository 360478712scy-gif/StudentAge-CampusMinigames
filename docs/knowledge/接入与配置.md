# 接入、配置与交付

## Steam 单 DLL 布局与 UP 前置
工坊包固定为 plugins/CampusMinigames.dll、EC2BUnofficialPatch/Minigame/、Cfgs/zh-cn/、readme/、preview.jpg 和 manifest.json。全部十二项注册 dll 指向 ../../plugins/CampusMinigames.dll。UP 是单独前置，不随包附带 UP DLL。完整结构和命令见 docs/REPOSITORY_LAYOUT.md。

## JSON 配置与作者覆盖
关卡数值位于 mod/Cfgs/zh-cn，各游戏一张表，通用 NDS/Audio/Social 参数在 CampusMinigameCfg。作者把需要改的行放入自己 Mod 的 Cfgs/zh-cn，加载时按规则合并，未指定的参数保留默认值；不能覆盖作者文件。MinigameTables/ModCfgLocator 实现读取；tools/tuning/settings.json 和 generate.py 生成默认表及说明。

## UP 社交阶段与剧情 miniGame
每个社交阶段的 startTalk 指向带 miniGame 的对话；TalkCfg/OptionCfg 的 miniGame 参数指定游戏与关卡，例如 [9102,3]。UpLevel 优先读剧情参数，再读社交阶段编号，不足时回到默认关卡。人物绑定、阶段条件、费用与结算需连同 UP 调用链核对；只有编辑器字段或注册 JSON 不能证明游戏中触发成功。

## 防止重复扣费与奖励
UpSession/IGameSession 管理会话；Begin 和 Finish 必须幂等，重开不重复扣费，读档取消不能伪造胜负。普通社交把结果交回 UP；NDS 练习和存档会话分开，进度/徽章按当前存档记录。涉及接口兼容时以实际 UP 程序集与游戏日志为证，不能只看版本号推断。

## 三国杀人物剧情与奖励
三国杀实现在 src/Games/Sanguosha，同一 DLL 编译；作者剧情、人物武将分配、失败不推进阶段与一次性奖励的约定见 docs/games/sanguosha/。覆盖配置前校验 Schema，保留原生对白、表情与性别分支。不要把早期测试记录中的商品时间或剧情编号当成当前 CFG。

## 构建、手动包与更新
build.py 编译一个 DLL；tools/assemble_mod.py 组装工坊目录；package_workshop.py 打工坊 ZIP；prepare_minigames_release.py 生成单目录手动安装/更新包。手动渠道使用 BepInEx/plugins/CampusMinigames 与 campus-minigames-v2；Steam 安装由 Steam 更新。旧双 DLL 客户端需手动迁移；历史部署脚本已归档，禁止用于当前包。
