## 不能混淆的证据
编译、独立规则测试、静态检查、隔离 CrossOver、原生 Windows、真实用户 Mod 是不同层次。目录整理没有新增原生 Windows 实机游玩验收；没有当前日志/截图时不能声称用户问题已复现或已修复。旧私人 QA 路径和历史通过记录不当作本仓库当前结果。

## 接近完工的多 agent 审计
每款小游戏主要功能接近完成后，默认三个子 agent 并行检查 UI 操作、玩法与 CFG/UP、稳定性与发布兼容。集中审计一轮，修复后最多一轮定向复核。阻断实质严重问题；轻微偏好登记后续，不要求建议清零。具体触发、分工、停止条件和证据格式见 docs/workflow/完工审计.md。

## 后续问题处理
UI 检查需要当前构建的实际画面和交互；事件/配置问题需要当前 Mod、编号、操作和保存前后数据；加载问题需要当前程序集及日志。没有足够证据时记录缺口并做可执行的定向检查，不凭历史笔记补出未经验证的结论。性能优化先测量，回归检查覆盖存档与资源生命周期。
